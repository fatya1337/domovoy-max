# Проверка собственного HTTP API

Контракт: openapi.json, OpenAPI 3.1.0 (https://spec.openapis.org/oas/v3.1.0.html). DATA-API.yaml описывает основные проверки по полям из PDF кейса. schema_version в нём — версия схемы команды, не подтверждённый формат валидатора организаторов. Постоянный HTTPS-адрес и учётные записи проверяющих ещё необходимо назначить; файл пока не готов к финальной сдаче без этих значений.

## Изолированная автоматическая проверка

`python3 -m venv .venv-dev`, затем `.venv-dev/bin/pip install -r requirements-dev.txt` и `.venv-dev/bin/python validate_api.py`.

Проверка валидирует спецификацию и запускает отдельный HTTP-сервер на случайном свободном локальном порту с временной БД и синтетическим токеном. Проверяет все 22 операции, форматы ответов, полный бытовой сценарий, приватность, конфликт версий, повтор отправки, запрет подмены роли заголовком демо и чужой Origin. Не обращается к MAX, не меняет рабочие контейнеры, удаляет только свою временную БД. Тестовые данные — fixtures/scenario.json.

## Режимы и права

В MAX нужен подписанный X-Max-Init-Data с возрастом не более часа; пользователь и роль не принимаются из тела. Для POST обязателен Origin, равный PUBLIC_ORIGIN. Host проверяется для всех запросов. JSON тела — менее 10000 байт, Content-Type строго application/json. Для webhook отдельный секрет и лимит 262144 байта. Не запускать webhook worker одновременно с poller одного токена.

В локальном демо вместо initData используется X-Demo-Profile: anna, boris, manager или dispatcher. Оно слушает только loopback и предназначено для вымышленных данных.

УК создаёт дома, заменяет приглашения, публикует объявления и аварии. Жители вступают по приглашению. Бытовые заявки и комментарии доступны участникам подъезда и УК. Статусы бытовой заявки: new → work → done → confirmed. УК ведёт работы, автор подтверждает done или возвращает в work. Обычная роль УК не может подтвердить чужой результат.

Аварии: reported → work → restored (допускается сразу restored); требуется version. Учебные обращения: saved → review/clarify/closed, review/clarify → review/clarify/closed. После closed добавление сообщений отключено. Автор и отдельный диспетчер читают историю и уточняют, только диспетчер меняет статус. Без TRAINING_INCIDENTS_ENABLED=1 учебные endpoints в MAX возвращают 403.

request_id необязателен для совместимости, клиент приложения всегда его передаёт. Повтор того же тела возвращает сохранённый результат; повтор ID с другим телом отклоняется. Ошибки ввода/устаревшей версии — 400, доступа — 403. Даты SQLite — UTC, интерфейс переводит их в часовой пояс устройства. Пагинации пока нет: лимиты указаны в спецификации и интерфейсе.

`POST /api/tickets` принимает необязательный `outage_id`. `POST /api/ticket/outage` меняет связь существующей заявки (поля `entrance_id`, `id`, `outage_id`; null снимает связь). Доступ — автор или УК, до подтверждения результата; новая связь допускается только с активной аварией того же дома. GET карточки возвращает `outage` с текущими сведениями либо null.
