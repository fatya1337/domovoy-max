# Бот с общей базой

Режим APP_MODE=max подключает connected_bot.py. Общие операции выполняет miniapp.py: одинаковые права, состояния заявок и история для обоих интерфейсов. Режим без APP_MODE=max сохраняет старый учебный бот.

## Житель

`/start` → «Вступить по коду» → приглашение УК → «Новая заявка» → категория → описание → подтверждение. Карточка `/ticket НОМЕР` содержит адрес, статус, последние события и действия. `/comment НОМЕР текст` добавляет комментарий. `/confirm НОМЕР` подтверждает выполненную заявку, `/reopen НОМЕР` возвращает её. «Объявления» показывает последние три объявления выбранного подъезда. `/home НОМЕР` переключает подъезд из списка «Мой дом». Отмена убирает черновик, но не обращения. `/archive` показывает прежние демозаявки из транспортной базы отдельно.

## УК

Роль берётся только из ADMIN_IDS. «Добавить дом» запрашивает название, адрес, количество подъездов и подтверждение. Приглашения находятся в «Мой дом». «Очередь УК» → карточка → `/status НОМЕР work` → `/status НОМЕР done`. Подтверждение результата принадлежит автору заявки. Расширенные объявления и управление приглашениями доступны в миниаппе.

## Надёжность

Черновики хранятся в bot_sessions. Результат обработки входящего события сохраняется в connected_replies в одной транзакции с изменением заявки. Если процесс остановится до записи ответа в транспортную outbox, повтор события вернёт тот же результат без повторного создания заявки. Некорректное действие откатывается через SAVEPOINT. Отправка сообщений использует прежнюю durable outbox. Poller доставляет также уведомления miniapp.app_outbox.

## Воспроизводимый запуск

На сервере с DNS и доступными 80/443 заполнить .env.pilot на основе .env.pilot.example. Проверить `python3 preflight.py --env .env.pilot` (точный интерфейс также указан в PILOT.md). Запуск:

```sh
docker compose --env-file .env.pilot -f compose.max.yaml up -d --build
```

Этот стек включает app, bot (Long Polling), HTTPS Caddy и общий volume. Webhook-вариант остаётся в compose.pilot.yaml. Одновременно эти стеки с одним токеном не запускать. Тесты: `python3 -m unittest -q`.

## Текущая установка на компьютере пользователя

`domovoy-connected-bot` запущен с data/preview.env, image domovoy-pilot:local, командой python bot.py poll. Общая база приложения: volume domovoy-preview-data → /app/data; MINIAPP_DATABASE_PATH=/app/data/preview.sqlite3. Транспорт, marker и архив прежних заявок: volume smart-city-bot_bot-data → /app/transport; DATABASE_PATH=/app/transport/bot.sqlite3. Старый smart-city-bot-bot-1 остановлен и restart=no. Резервная копия транспортной БД: before-shared-bot.sqlite3 внутри этого volume.

Для отката сначала остановить domovoy-connected-bot, затем включить старому контейнеру restart=unless-stopped и запустить его. Volumes не удалять. При обновлении новой версии сохранять оба mount и пути БД. Не запускать второй poller. Локальная страница localhost:8765 остаётся отдельной демонстрацией с вымышленными профилями; это не база пилота.

Публичный HTTPS-адрес может истечь. От его доступности текстовый бот не зависит. Пока MINIAPP_ENABLED=0, кнопка запуска миниаппы отсутствует. Перед включением проверить привязку организаторами.

## Кнопки отчёта и комментария

В карточке заявки УК видит «Взять в работу №…» и «Работа выполнена №…». При выполнении бот запрашивает пояснение отдельным сообщением и сохраняет его в истории. Автор видит «Всё исправлено №…» и «Проблема осталась №…»; при возврате бот запрашивает, что нужно доделать. «Комментарий к заявке №…» также открывает ввод отдельным сообщением. Отмена оставляет существующую заявку без изменения. Старые команды /status, /comment, /confirm и /reopen поддерживаются. Перед записью права и текущий статус проверяются заново.
