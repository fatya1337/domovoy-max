# Временное подключение по HTTPS

Поднято 20.09.2026:
https://shoe-manager-bases-porcelain.trycloudflare.com

Это Quick Tunnel Cloudflare для проверки, не постоянный хостинг. Адрес доступен,
пока работают компьютер, Docker и процесс cloudflared; при повторном создании
туннеля адрес изменится. Для сдачи нужен постоянный адрес.

## Текущее состояние

- Cloudflared проксирует только http://127.0.0.1:8766.
- Контейнер `domovoy-https-preview` запускает режим MAX и отдельную базу пилота.
- Том: `domovoy-preview-data`; данные не смешиваются с локальным демо.
- Серверные настройки находятся в `data/preview.env` (права 600, исключён из Git/архивов).
- В качестве сотрудника пилота назначен аккаунт пользователя, проверенный командой `/id`
  в открытом чате бота. Произвольный посетитель не может выбрать роль УК.
- Без подписанного входа запрос /api/state получает 403; /.env получает 404.
- /health и /api/config доступны публично и не содержат секретов.
- Форма организаторов НЕ отправлялась:
  нужны ФИО, регистрационный email капитана и название команды.
- Webhook на временный URL НЕ зарегистрирован; существующий бот продолжает Long Polling.
- Новый `domovoy-connected-bot` работает через Long Polling с этой же базой. Он доставляет уведомления из app_outbox. Старый контейнер остановлен, его данные сохранены. Кнопка открытия мини-приложения пока не включена.

## После прикрепления URL

1. Проверить открытие приложения внутри MAX и подпись реального входа.
2. После подтверждения привязки установить MINIAPP_ENABLED=1 и перезапустить подключённый бот. Long Polling можно сохранить.
3. Если переходить на Webhook, сначала остановить domovoy-connected-bot, затем запустить worker и зарегистрировать подписку. Не запускать оба режима одновременно.
4. Пройти сценарий двумя аккаунтами, проверить уведомления в реальном MAX.

Нельзя считать привязку готовой по одной лишь доступности HTTPS.

## Остановка

`docker stop domovoy-https-preview` останавливает приложение и сохраняет том.
Процесс туннеля можно найти командой
`pgrep -fl 'cloudflared tunnel --url http://127.0.0.1:8766'`
и завершить соответствующий процесс. Не останавливать чужие туннели.
