# Архив первого учебного бота

Этот документ сохранён для старого режима bot.py без APP_MODE=max. Он не описывает текущее состояние Домового и не является планом дальнейшей работы. Текущие инструкции — README.md и OPERATIONS.md. Утверждения о ещё не существовавшей миниаппе и будущих этапах ниже относятся к ранней версии.

## Прежний учебный режим

Текстовый бот, кнопки меню, черновик заявки, подтверждение перед сохранением,
личные заявки, роль сотрудника, статусы и уведомления, подтверждение результата
или возврат на проверку. Заявки и черновики сохраняются в SQLite.
Это учебный прототип: реальные УК, 112, Госуслуги Дом и GigaChat **не подключены**.
Используйте вымышленные данные. Добавлен отдельный локальный прототип мини-приложения: см. MINIAPP.md. К MAX он пока не привязан.

## Запуск

Требуется Python 3.12+ либо Docker с Compose. Сторонних Python-пакетов нет.
В уже подготовленной рабочей папке `.env` существует и содержит токен.
При переносе скопируйте `.env.example` в `.env` и заполните токен локально.
Не перезаписывайте существующий `.env` и не публикуйте его.

```sh
python3 bot.py check
python3 bot.py poll
```

Все локальные компоненты одной командой:

```sh
docker compose up --build -d
```

Остановка: `docker compose stop`. Повторный запуск: `docker compose up -d`.
При запуске Python остановка — Ctrl+C, повторный запуск — `python3 bot.py poll`.
Не запускайте одновременно два экземпляра с одним токеном. Бот работает,
пока работает процесс и компьютер имеет доступ к сети.
Docker использует отдельный постоянный том `bot-data`; локальный Python — `data/`.
Не удаляйте Docker-том, если хотите сохранить заявки.

## Настройки и архитектура

- `MAX_BOT_TOKEN`: серверный секрет, обязателен.
- `MAX_API_BASE`: только `https://platform-api2.max.ru`.
- `MAX_CA_FILE`: дополнительный сертификат для TLS только запросов к MAX.
  По умолчанию `certs/russian_trusted_root_ca.pem`. Проверка TLS включена.
  Системное хранилище сертификатов не изменялось.
- `ADMIN_IDS`: числовые MAX user_id сотрудников через запятую. По умолчанию
  пусто: никто не получает административный доступ автоматически.
- `DATABASE_PATH`: путь SQLite, по умолчанию `data/bot.sqlite3` рядом с кодом.

MAX → Long Polling → обработчик команд → SQLite → очередь ответов → MAX.
Входящие события дедуплицируются. Обработка события и создание исходящих
ответов проходят в одной транзакции. При сетевой ошибке ответы повторяются.
Если MAX принял ответ, но соединение оборвалось до подтверждения, возможен
повтор исходящего сообщения; повтор входящего события не создаёт вторую заявку.
Один процесс обслуживает запросы последовательно; масштабная нагрузка пока
не поддержана. Текстовые поля ограничены по длине, бот работает в личном диалоге.
Доступ к заявкам проверяется по отправителю MAX, сотрудникам — по ADMIN_IDS.

В прежнем режиме работает только бот. В полном стеке миниаппа обслуживает HTTP API на внутреннем порту 8765, Caddy публикует HTTPS на 443; контракт в openapi.json.
Исходящие запросы: HTTPS 443 к MAX. Чужие Webhook-подписки автоматически
не удаляются: при наличии подписки запуск прекращается с объяснением.

Для текущего пилота используется Long Polling. Альтернативный webhook ingress с проверкой секрета и отдельным worker реализован в compose.pilot.yaml. Эти способы получения событий нельзя запускать одновременно для одного токена. Промышленный мониторинг и регламент резервного копирования требуют отдельной настройки.

## Проверка командой

1. Запустить бот, открыть ссылку и нажать «Начать» или написать `/start`.
2. «Новая заявка» → «Тестоград, Примерная, 1» → «Не горит лампа на втором этаже».
3. До подтверждения заявки в базе нет. Нажать «Подтвердить заявку»; получить номер.
4. «Мои заявки» показывает зарегистрированную заявку.
5. Для роли сотрудника: написать `/id`, внести полученный ID в ADMIN_IDS
   в локальном `.env`, перезапустить процесс. В Docker: `docker compose up -d --force-recreate`.
6. Сотрудник: `/queue`, затем `/status 1 work` и `/status 1 done` (подставить номер).
7. Житель получает обновления, пишет `/confirm 1` либо `/reopen 1`.
8. Другой пользователь не может открыть чужую заявку или изменить её статус.
9. «Экстренная помощь» показывает номер 112 и явно сообщает, что службы не вызваны.

Автоматическая проверка:

```sh
python3 -m unittest -v
```

Тесты не используют реальные токены и не отправляют сообщения в MAX.

## Границы первой версии

- Нет подключения к 112, Госуслугам, реальной УК или GigaChat. Нет имитации успешной отправки им.
- Нет фотографий, распознавания речи, определения координат, поиска похожих заявок,
  подписок соседей, справочника домов, мини-приложения и автоматической маршрутизации.
- Проверка отдельных слов об опасности — дополнительная подсказка, а не классификатор:
  она может пропустить опасность или сработать ошибочно. Кнопка 112 доступна всегда.
- Подтверждение результата — обратная связь внутри прототипа, не официальный акт приёмки.
- Для production нужны политика хранения/удаления данных, управление организациями
  и их сотрудниками, проверка привязки к дому, Webhook и хостинг.
- Не проверено на устройствах команды в мобильном и веб-клиенте MAX.
- PDF-презентация и финальный комплект сдачи ещё не подготовлены.

   ФИО и регистрационный email капитана, название команды, URL. Форма не отправлялась.
