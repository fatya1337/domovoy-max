# Домовой — бот и мини-приложение MAX

Домовой объединяет жителей одного дома и управляющую компанию: приглашение в подъезд → заявка → работа УК → отчёт → подтверждение или возврат жителем. Бот и миниаппа используют одну SQLite-базу и общие правила доступа.

Обновлено 27 сентября 2026. Команда salfetka5: Фатькин Артем, Дзюбло Григорий. Бот: [Хакатон МАХ 738](https://max.ru/t738_hakaton_max_bot), миниаппа: https://domovoy-doma.ru/. Публичный сервер и HTTPS работают; проверены вход УК, создание учебного дома и повторный вход в веб-MAX. Полный сценарий с отдельным жителем и мобильным клиентом ещё требует проверки. Для жюри: [REVIEWER-GUIDE.md](REVIEWER-GUIDE.md).

## Возможности

- Дома, подъезды, приглашения, обсуждения и объявления с отметками ознакомления.
- Заявки с категориями, комментариями, историей и подтверждением результата автором.
- Очередь УК по всем домам одного экземпляра приложения.
- Общие аварии: причина, прогноз, статусы и уведомления участников домов. Заявку можно связать с аварией; её восстановление не закрывает заявку автоматически.
- Пошаговый бот: создание дома и заявки, выбор подъезда, комментарии, отчёт о работе и возврат заявки кнопками.
- Приватные учебные обращения и отдельная роль учебного диспетчера. В живом MAX этот режим по умолчанию выключен.
- Проверка подписи MAX, серверные роли, защита от повторной записи при доставке одного события и повторе запроса. При потере ответа интерфейс сохраняет идентификатор операции для повторной отправки неизменённых полей в той же вкладке.

Реальных интеграций с 112/МЧС, Госуслугами и GigaChat нет. Их развитие описано в [концепции](docs/PRODUCT-VISION.md). Учебное обращение никого не вызывает. При опасности пользователь должен звонить 112. Права нескольких независимых УК пока не разделены: один экземпляр предназначен для одной организации.

## Посмотреть локально

Нужен Python 3.12 или новее, сторонние библиотеки для приложения не требуются:

```sh
python3 miniapp.py
```

Откройте http://127.0.0.1:8765/. Локальные роли Анны, Бориса, Марии и учебного диспетчера вымышленные. Демонстрационная база отделена от пилота MAX; не вводите реальные данные соседей. Подробности интерфейса — [MINIAPP.md](MINIAPP.md).

## Разместить и подключить MAX

1. Подготовить постоянный сервер, HTTPS-имя и `.env.pilot` по `.env.pilot.example`; файл хранить с правами 600. Не размещать секреты в репозитории, презентации или форме ссылки.
2. Проверить настройки: `python3 preflight.py --env .env.pilot`.
3. Остановить прежний poller этого токена перед переносом. Запустить стек:

```sh
docker compose --env-file .env.pilot -f compose.max.yaml up -d --build
```

4. Проверить публичный адрес: `python3 check_release.py https://ВАШ-АДРЕС`.
5. Подать ссылку организаторам, дождаться привязки, включить MINIAPP_ENABLED и проверить сценарии реальными тестовыми аккаунтами в мобильном и веб-MAX.

Стек: app, bot Long Polling, Caddy, backup. Не запускать одновременно несколько получателей событий одного токена. Остановка без удаления данных: `docker compose --env-file .env.pilot -f compose.max.yaml down` (без `-v`). Подробности размещения, копирования и восстановления — [OPERATIONS.md](OPERATIONS.md); порядок подачи — [SUBMISSION.md](SUBMISSION.md). Текущие ограничения выпуска — [RELEASE-STATUS.md](RELEASE-STATUS.md), заметки о бюджете — [HOSTING-NOTES.md](HOSTING-NOTES.md).

## Проверки

```sh
python3 -m unittest discover -v
node --test test_request.js
```

73 Python-теста и 6 тестов JavaScript прошли. Они используют синтетические данные и не отправляют сообщения настоящим пользователям. Проверка HTTP-контракта всех 22 операций и изолированный Compose выполняются из окружения с `requirements-dev.txt`:

```sh
python validate_api.py
python smoke_stack.py
```

`smoke_network_ui.py` запускает отдельный локальный стенд с временной базой для проверки обрывов ответа в браузере. Инструкция и результаты ручной проверки — [QA-REPORT.md](QA-REPORT.md). Локальная проверка не заменяет испытание окончательного размещения внутри MAX.
