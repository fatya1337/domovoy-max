# Подключение Домового внутри MAX

Подготовлено 20.09.2026. Это пакет для пилота одной УК. На публичный сервер
он ещё не развёрнут, мини-приложение к боту ещё не прикреплено.
Для временного HTTPS-доступа с этого компьютера см. [TEMP-PREVIEW.md](TEMP-PREVIEW.md).

## Реализовано

- Режим `APP_MODE=max`: загрузка MAX Bridge, передача initData серверу,
  проверка HMAC-SHA256 по официальной схеме, уникальности параметров,
  времени входа (1 час, допуск будущего времени 30 секунд), ID пользователя.
- Сервер назначает роль УК только по `ADMIN_IDS`. `X-Demo-Profile` в этом
  режиме игнорируется; вместо тестовых имён используются данные подписанного входа.
- Отдельная чистая база пилота, без Анны, Бориса, Марии и демонстрационных домов.
- Дома, подъезды, приглашения, обсуждения, объявления и заявки привязаны к MAX ID.
- Бот в режиме пилота читает «Мои заявки» из той же базы, что приложение.
  Заявки создаются и обрабатываются в приложении; старый текстовый мастер
  остаётся только в локальной версии, без автоматической миграции старых тестов.
- Смена статуса создаёт уведомление автору в постоянной очереди.
- HTTPS Webhook `/webhook` проверяет `X-Max-Bot-Api-Secret`, сохраняет событие
  и отдаёт ответ. Отдельный worker обрабатывает события и отправляет уведомления.
- Повтор событий не создаёт повторные заявки/операции. При потере сетевого
  подтверждения уже отправленное сообщение может быть доставлено повторно.
- Неотправленные ответы с HTTP 400/403/404 помечаются `sent=-1`, не мешают
  другим адресатам и остаются в базе для разбора. Сетевые ошибки повторяются.
- Docker-конфигурация приложения, worker и Caddy для HTTPS.

## Что ещё нужно от команды

1. VPS с Docker Compose и доменом, A/AAAA записи которого указывают на VPS.
2. Доступные извне порты 80 и 443. Порт приложения 8765 наружу не публикуется.
3. MAX ID назначенного сотрудника УК. Получить через `/id` в существующем боте.
4. ФИО, регистрационный email капитана и название команды для формы организаторов.
5. Прикрепление публичного URL организаторами и проверка в настоящих клиентах MAX.

## Развёртывание

На сервер перенести исходники и публичные сертификаты; не переносить локальные
демо-базы и не публиковать `.env` в Git. Создать `.env.pilot` из `.env.pilot.example`
с правами 600, заполнить токен только на сервере. `MAX_WEBHOOK_SECRET` — случайная
строка, например результат `python3 -c 'import secrets; print(secrets.token_urlsafe(32))'`.
Не отправлять секрет в чат и не включать в форму организаторов.

Установить `APP_DOMAIN`, `PUBLIC_ORIGIN=https://ваш-домен`, `ADMIN_IDS`.
`MINIAPP_ENABLED=0` оставить до подтверждённой привязки URL.

```sh
docker compose --env-file .env.pilot -f compose.pilot.yaml up --build -d
```

Проверить публичный `/health`: должен отвечать 200. Caddy автоматически получает
TLS-сертификат при доступном домене. Проверить `docker compose ... logs`.
Открытие приложения в обычном браузере должно предложить открыть его из MAX,
а не предоставлять выбор чужого аккаунта или доступ к данным.

Перед переключением событий остановить старый Long Polling на текущем компьютере:
`docker compose stop bot`. Затем на VPS зарегистрировать Webhook:

```sh
docker compose --env-file .env.pilot -f compose.pilot.yaml exec app python register_webhook.py
```

Скрипт не меняет чужую Webhook-подписку. Ранее созданные локальные тестовые заявки
сохраняются в прежнем Docker-томе. Для обратного перехода нужно сначала снять
подписку Webhook, затем включить Long Polling; автоматический откат не выполняется.

## Прикрепление мини-приложения

В форму https://sbor-ssylok-dlya-mini-prilojeniy.testograf.ru/ передать публичный
HTTPS URL корня приложения, данные капитана и название команды.
Не отправлять `/webhook`, localhost или токен вместо URL.
После подтверждённого прикрепления установить `MINIAPP_ENABLED=1` и пересоздать
worker командой `docker compose --env-file .env.pilot -f compose.pilot.yaml up -d`.
Отправить `/start` боту: он покажет кнопку «Открыть Домового».

## Проверка после привязки

1. Назначенный аккаунт УК открывает приложение внутри MAX, создаёт дом и подъезды.
2. Второй MAX-аккаунт вступает по коду и создаёт заявку.
3. В чате этого аккаунта «Мои заявки» показывает именно эту заявку.
4. УК меняет статус. Автор получает уведомление в боте и подтверждает результат.
5. Сосед другого подъезда не видит чужое обсуждение; смена заголовка demo-профиля
   не даёт ему права УК.
6. Повторить в мобильном и веб-клиенте. Проверить открытие кнопкой, MAX Bridge,
   встраивание/CSP и действительные подписанные стартовые данные.

## Практические ограничения

Вход и HTTP проверены локально синтетическими подписанными данными; реальный
вход из MAX ещё нельзя проверить до привязки. Один пилот — одна организация:
все назначенные сотрудники УК видят все дома этой установки.
Нет самостоятельной регистрации УК, проверки права проживания, отзыва приглашений,
модерации сообщений, резервного копирования по расписанию и ограничения частоты запросов.
Приглашение пока многоразовое; храните его у участников ограниченного пилота.
Для расширения на нескольких УК потребуется отдельная модель организаций.
Нет интеграций 112/Госуслуги/GigaChat. Это не сервис экстренной помощи.

Данные сохраняются в Docker-томе `pilot-data`. Не использовать `down -v`:
это удаляет том. До реального пилота настроить резервные копии через SQLite backup,
сроки хранения и удаление данных. При обновлении делать резервную копию тома.

## Результаты проверки 20.09.2026

- 31 автоматический тест: подпись входа, роли, права по подъездам, Webhook,
  настройки публикации и полный сценарий от создания дома до уведомления жителя.
- Полный сценарий использует настоящий локальный HTTP-сервер, SQLite и worker;
  исходящие вызовы MAX заменены тестовым приёмником. Это не проверка доставки в MAX.
- Docker-образ запускается: HTTP health отвечает 200, подмена demo-профиля
  в режиме MAX отклоняется с 403. Ранее наблюдавшееся зависание Docker не повторилось.
- Конфигурация Caddy проверена в контейнере. Публичный сертификат ещё не получен.
- Compose проверен; worker и HTTPS-прокси запускаются после успешной healthcheck приложения.
- Старый локальный бот продолжает работать. Публичный сервер ещё не настроен.
- Настоящие initData MAX, публичный Webhook и открытие приложения в MAX остаются
  непроверенными до размещения и прикрепления URL организаторами.

## Повторение проверок

```sh
python3 -m unittest -q
docker build -f Dockerfile.app -t domovoy-pilot:local .
python3 smoke_pilot.py
python3 preflight.py --env .env.pilot
```

smoke_pilot.py использует синтетические ключи, временные контейнеры и порт 18765
только на 127.0.0.1. Сам удаляет свои контейнеры, не трогает действующий бот.
preflight.py проверяет заполнение настроек и права файла, не выводит секреты,
не регистрирует Webhook и не отправляет данные организаторам.
